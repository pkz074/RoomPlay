Environment: Windows amd64, Go 1.26.0; 64-bit MSYS2 GCC for race builds.
The process harness builds module-pinned NATS Server v2.15.3 and the repository
coordinator, library and player executables. It starts three simulated room players
on loopback ports, with separate OS processes for all components.

Verified:
- Registration and independent room state; real HTTP/NATS request/reply and SSE.
- Queue occurrence add/remove/clear, playback navigation and Stop versus Clear.
- Stop then Play of the retained selected track restarts at zero without adding
  history or changing queue/current occurrence. Repeated cycles and delayed old
  completion callbacks are covered by deterministic tests.
- Serial and 16 concurrent identical request IDs execute once; conflicting reuse
  is rejected. Distinct same-room and cross-room requests retain every mutation.
- A healthy room completes a command while another room waits for a lost reply.
- Missed SSE state is recovered by an authoritative HTTP snapshot after reconnect.
- Duplicate player process rejected; retired instance publications ignored.
- Forced player crash: HTTP 503 NO_RESPONDERS; offline detection about 5.9 seconds.
  Restart creates a fresh instance with empty in-memory state.
- Forced coordinator and broker restarts: existing player occurrence/playback
  survives; registration/state recover; no queued mutation replay.
- Lost response: one delivery, HTTP 504 COMMAND_TIMEOUT with unknown outcome,
  no transparent retry. Broker outage: HTTP 503 BROKER_UNAVAILABLE.
- Actual MP3 delivery; audio path allowlist/traversal rejection; library rejects
  an unlicensed catalog. Owned child processes stop and release fixtures.
- Live browser controls, independent rooms, queue add/remove and refresh.
  Fixed a rendering failure caused by calling String.toUpper instead of toUpperCase.

Limits:
